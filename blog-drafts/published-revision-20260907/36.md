# UU 连不上，最后查到了残留的代理变量

![电脑、断开的本地代理节点与重新连通的网络](/article-covers/proxy-troubleshooting.png)

本来想和朋友联机玩我的世界，打开 UU 却连不上，后来 VPN 也不正常。浏览器倒是还能打开网页。

我查了系统代理、DNS、路由、防火墙，也试过网络重置和手机热点。换了网络还一样，就开始怀疑问题在这台电脑上。

后来用命令行测连接：

```powershell
curl.exe -I https://www.microsoft.com
```

报错里出现了 `over proxy 127.0.0.1`。请求居然还在走本地代理。顺着查下去，用户环境变量里留着这几项：

```text
HTTP_PROXY=socks5h://127.0.0.1:65532
HTTPS_PROXY=socks5h://127.0.0.1:65532
ALL_PROXY=socks5h://127.0.0.1:65532
```

但这个端口对应的代理已经没在运行了。会读取这些变量的程序，仍然把请求交给它，连接自然失败。浏览器可能用了不同的代理设置，所以还能正常上网。

## 留一下当时的检查步骤

先看当前终端和用户级配置，两处都要查：

```powershell
Get-ChildItem Env:*_PROXY

Get-ItemProperty 'HKCU:\Environment' |
  Select-Object HTTP_PROXY, HTTPS_PROXY, ALL_PROXY
```

再对比正常请求和绕过代理的请求：

```powershell
curl.exe -I https://www.microsoft.com
curl.exe --noproxy "*" -I https://www.microsoft.com
```

如果前一条失败，后一条成功，就先检查代理配置。这里还查了变量指向的端口有没有程序监听：

```powershell
Get-NetTCPConnection -LocalPort 65532 -State Listen -ErrorAction SilentlyContinue
```

65532 是我这次遇到的端口，排查时要看自己变量里写的地址。

## 确认不用这个代理后再清理

这些变量如果是正在使用的代理配置，就应该先检查代理程序。我这里确认是残留项，才删掉用户级变量：

```powershell
[Environment]::SetEnvironmentVariable('HTTP_PROXY',  $null, 'User')
[Environment]::SetEnvironmentVariable('HTTPS_PROXY', $null, 'User')
[Environment]::SetEnvironmentVariable('ALL_PROXY',   $null, 'User')
```

当前 PowerShell 窗口里已经继承的变量也清掉：

```powershell
'HTTP_PROXY', 'HTTPS_PROXY', 'ALL_PROXY' | ForEach-Object {
  Remove-Item "Env:$_" -ErrorAction SilentlyContinue
}
```

改完还得完全退出受影响的软件，再重新打开。已经运行的程序可能还拿着旧变量，只改配置不一定马上生效。

最后重测拿到了 `HTTP/1.1 200 OK`，重新打开 UU 也恢复了。折腾了一圈，留这份记录，下次浏览器正常、应用连不上时，先看一下代理变量。
