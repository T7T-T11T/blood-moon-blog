# 我的博客现在部署在哪里

这个博客用 Vue 写前端，生产后端放在 Cloudflare Workers，数据存在 Supabase。选这套组合，主要是想先把网站放上去，不用自己买一台服务器再配置环境。

几个部分这样连接：

```text
浏览器 → Cloudflare Pages（前端页面）
       → Cloudflare Workers（API）→ Supabase（数据库）
```

## 页面、接口和数据

Pages 放的是 Vite 构建出来的前端文件。读者打开页面后，文章列表、正文这些数据再从 Workers 的 API 获取。

Workers 后端用 Hono 写路由，负责文章、分类、评论等接口，也生成 RSS 和 Sitemap。数据库通过 Supabase SDK 访问，表结构的修改放在迁移脚本里。

前端和 API 的域名不同，所以后端要配置 CORS，允许博客页面发来的请求。本地开发现在也复用已部署的 Worker，由 Vite 转发 `/api` 请求。这一点和最早在本地跑 Express 的方式已经不一样了。

## 部署时处理过的问题

之前试过给 API 加代理，没有顺利跑通，后来改成前端直接请求 Workers。旧文章把这段经历写成了“Pages Functions 不支持外部 fetch”，这个结论下得太大了。那次代理没有跑通，并不足以说明平台没有这项能力。

CORS 配置也容易漏。前端域名换了，后端允许的来源没有跟着改，浏览器就可能拦截请求。

还有 RSS 和 Sitemap。早期访问对应地址，拿到的居然是前端页面，并不是 XML。后来才在 Workers 补上接口，把前端的跳转也接好。页面能打开的时候，这种问题很容易没注意到。

## 现在怎么发布

代码推到 `master` 后，GitHub Actions 会先做前端检查和测试、Worker 类型检查，再构建前端，依次部署 Worker 和 Pages，最后跑线上冒烟检查。

所以现在前后端都在同一条部署流程里，不再像早期那样单独手动发后端。数据库地址和密钥通过部署环境配置，不写进前端代码。

我当初是按免费额度能覆盖个人博客的思路选的服务。不过托管省掉的是一部分服务器配置，接口慢、数据库出问题、部署失败，还是要自己查。这个博客后面也遇到过这些事，慢慢修就是了。
