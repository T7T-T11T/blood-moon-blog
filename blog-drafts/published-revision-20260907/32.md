# Git 推不上去：查 hosts，再试 SSH 443

有次想把博客代码推到 GitHub，一直连接失败：

```text
fatal: unable to access 'https://github.com/...': Failed to connect to github.com:443
```

`gh auth status` 也报 token 无效，网页访问时好时坏。我先查了连接，没急着换 token。

## hosts 里留了指向本机的规则

检查域名解析时，发现 `github.com` 被解析到了 `127.0.0.1`。再打开 hosts，里面不止一条相关记录，`api.github.com`、`raw.githubusercontent.com` 等也被指向本机。

对应的本地服务没有运行，请求就到不了 GitHub。先备份 hosts，再清理这些异常条目、刷新 DNS，网页和 API 恢复了。

但 Git 的 HTTPS 连接还不稳定，有时会被重置。到这里，至少能把两个问题分开：hosts 的异常已经处理，Git 传输还需要继续测。

## 后来换成了 SSH 443

当时测试 `ssh.github.com` 的 443 端口可以连接，于是把仓库改成走 SSH。下面留一下配置过程。

如果没有 SSH 密钥，可以生成一对：

```bash
ssh-keygen -t ed25519 -C "你的邮箱" -f ~/.ssh/id_ed25519
```

已有这个文件的话，先检查现有密钥，不要直接覆盖。然后把 `id_ed25519.pub` 的公钥内容添加到 GitHub 的 **Settings → SSH and GPG keys**。

在 `~/.ssh/config` 里配置：

```text
Host github.com
  HostName ssh.github.com
  Port 443
  User git
```

测试认证，再切换仓库地址：

```bash
ssh -T git@github.com
git remote set-url origin ssh://git@github.com/你的用户名/仓库.git
```

这次切换以后，推送恢复了。它适合我当时的连接情况，不保证换一个网络也一样有效。

## 还有 URL 重写规则

全局 Git 配置里如果留着下面这种规则，会把 `git@github.com:` 开头的地址重新改成 HTTPS：

```text
url.https://github.com/.insteadof=git@github.com:
```

于是看着已经切到 SSH，实际仍然走回了原来的连接。上面用的 `ssh://` 写法不匹配这条前缀；如果配置里还有别的重写规则，也得一起检查。

浏览器能打开网页，不能直接说明 Git 也能连。它们使用的代理和连接方式可能不同。对我这次的问题，先修 hosts，再单独测试 Git 的传输方式，比反复重试 push 更有用。
