# 硬盘坏了，项目只找回了旧版本

![手机里的彩色表情、云端备份和创作工具](/article-covers/emoji-rebuild.png)

硬盘坏掉之后，本地项目只剩下很早的版本。云端还留着一些数据，文件也没有全丢，但最新改到哪里，我一时说不清。

这才麻烦。打开一个目录，不知道它是不是最新的；想接着改，又得先确认以前做过什么。代码之外，临时改过的配置、没整理的文档，也得一点点找。

以前总觉得等项目做得像样一点，再传到仓库。结果出事的时候，电脑上那些没推上去的修改，远程当然也不会有。

现在我会早点建仓库。哪怕刚开始只有 README，也先把它放上去。做完一个能跑的阶段，就提交、推送，顺便写一下这次改了什么。我的 GitHub 上因此多了几个还很空的项目，先留着，后面慢慢做。

![我的博客仓库卡片](https://opengraph.githubassets.com/1/T7T-T11T/blood-moon-blog)

博客仓库在这里：[blood-moon-blog](https://github.com/T7T-T11T/blood-moon-blog)。前端、后端、数据库迁移和部署说明都放在里面。其他项目有些还没开始写，有些是私人内容，就不逐个贴了。

## 小程序恢复起来比想的麻烦

恢复 Emoji 说的时候，我最先想把页面弄回来。等页面能打开了，才开始逐项看旧数据：以前的作品还显示吗，旧字段和现在的代码对得上吗，云函数是不是对应的版本，换个账号能不能看到图片。

这些都需要单独核对。项目目录找回来，并不能说明云端和本地已经对上了。

后来补了旧字段兼容，也整理了部署步骤、真机验收和维护说明。这部分没多少新功能可展示，但恢复项目时确实绕不过去。

代码之外的数据也得另外备份。Git 仓库里有提交记录，不代表数据库和上传的图片就一起存好了。

这次之后，我想先把几件小事做稳：代码及时推到远程，重要数据留备份，部署过程写下来。下次换电脑或者再出故障，至少能知道该从哪个版本接着做。
