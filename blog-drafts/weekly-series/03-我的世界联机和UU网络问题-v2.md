这件事的起因其实很简单。

我想和朋友联机玩我的世界，所以开了 UU。结果 UU 连不上，后来 VPN 也不正常。但最离谱的是：浏览器能正常打开网页。

你说它没网吧，不对；你说它有网吧，我需要用的软件又偏偏不行。

这种“坏一半”的网络问题真的很折磨人。它不像完全断网，重连一下路由器、换个 Wi-Fi 就有明显方向。它是每个现象都在给你一点希望，然后又让你继续怀疑下一个地方。

我当时一路查了不少：网络重置、系统代理、IP、DNS、路由、防火墙、BFE、WLAN 绑定、IPv4/IPv6，甚至还换了手机热点。

热点也没用的时候，我才慢慢意识到：这可能不是路由器的问题，也不是某一个 Wi-Fi 的问题。因为它跟着这台电脑走。

## 浏览器正常，反而是一个重要线索

一开始“浏览器能上网”会让人觉得更迷惑。后来我才明白，它其实不是一句废话。

它至少说明基础网络链路大概率还活着。真正要问的是：为什么浏览器和 UU、VPN、命令行工具走的不是同一条路？

我后来用 `curl` 单独做了一次联网测试：

```powershell
curl.exe -I https://www.microsoft.com
```

关键报错里出现了：

```text
over proxy 127.0.0.1
```

这句话一下就把范围缩小了。

请求不是直接出去的，它被送到了我自己电脑上的一个代理地址。继续看以后，发现用户环境变量里还留着几条以前代理软件写进去的配置：

```text
HTTP_PROXY=socks5h://127.0.0.1:65532
HTTPS_PROXY=socks5h://127.0.0.1:65532
ALL_PROXY=socks5h://127.0.0.1:65532
```

问题就在这里。

那个本地 SOCKS5 代理已经没有正常运行了，可新启动的程序还是会读到这几条变量，然后把网络请求全部交给 `127.0.0.1:65532`。等于它们还没碰到互联网，就先撞在了自己电脑里一扇已经关掉的门上。

浏览器为什么没事？因为它可能用自己的代理设置、自己的连接或自己的网络策略，没有完全跟着这些环境变量走。所以“浏览器能上网”不代表所有程序都没问题。

## 我最后怎么查、怎么修的

下面是我实际留下来的检查步骤。先说明：**不要看到命令就直接清空变量**。先确认它们是不是确实指向一个你已经不用、也没有服务在监听的代理端口。

### 1. 看当前终端里有没有代理变量

```powershell
Get-ChildItem Env:*_PROXY
```

### 2. 看 Windows 用户级持久变量

```powershell
Get-ItemProperty 'HKCU:\Environment' |
  Select-Object HTTP_PROXY, HTTPS_PROXY, ALL_PROXY
```

### 3. 用“绕过代理”的请求做对照

```powershell
curl.exe -I https://www.microsoft.com
curl.exe --noproxy "*" -I https://www.microsoft.com
```

如果普通请求失败，但 `--noproxy "*"` 成功，就很值得优先看代理变量。

### 4. 看本地端口到底有没有程序在监听

```powershell
Get-NetTCPConnection -LocalPort 65532 -State Listen -ErrorAction SilentlyContinue
```

没有任何结果，不代表所有网络问题都由它造成；但如果变量正好指着这个端口，而端口没人监听，方向就很明确了。

### 5. 确认是残留配置后，再清掉用户级变量

```powershell
[Environment]::SetEnvironmentVariable('HTTP_PROXY',  $null, 'User')
[Environment]::SetEnvironmentVariable('HTTPS_PROXY', $null, 'User')
[Environment]::SetEnvironmentVariable('ALL_PROXY',   $null, 'User')
```

当前 PowerShell 窗口里的变量也可以清掉：

```powershell
'HTTP_PROXY', 'HTTPS_PROXY', 'ALL_PROXY' | ForEach-Object {
  Remove-Item "Env:$_" -ErrorAction SilentlyContinue
}
```

然后重点来了：**完全退出 UU、VPN、终端等受影响的软件，再重新打开。** 变量通常在程序启动时继承，光改完配置不重启程序，它可能还抓着旧地址不放。

我最后重新测试，收到了：

```text
HTTP/1.1 200 OK
```

再打开 UU，终于恢复了。

## 这次我学到的，不是“记住一条命令”

我以前遇到网络问题，总想先找一个大招：网络重置、修复工具、重装、乱点一圈。现在我更愿意先问：这个问题到底发生在哪一层？

浏览器能用、应用不能用；换热点没用；报错还提到了本地代理。这些线索拼起来，比继续重置网络有用得多。

本来只是想和朋友联机玩个我的世界，最后顺手给未来的自己留了一篇网络故障笔记。

也算没白折腾。
